# EasyReforge タスク実装ワークフロー (Antigravity専用)

ユーザーから `「/workflow1 Task X.Y をやって」` のように特定のタスク番号を指定して依頼された場合、以下のステップを**必ず順番に**実行してください。

## Step 1: コンテキストの取得（文書の読み込み）

コードを書き始める前に、必ず `view_file` ツールを使って以下のファイル群を読み込んでください。

1. `docs/INDEX.md`
   プロジェクト全体のグローバルルール（`uv` の絶対採用、環境変数カスケードなど）を把握するため。
2. `docs/04_reference/04_reference_checklist.md`
   依頼されたタスクの完了状況を確認し、どの「Phase」に属するタスクなのかを特定するため。
3. `docs/03_implementation/03_implementation_phaseX.md` (Xは特定したPhase番号に書き換え)
   該当タスクにおける具体的な実装手順、注意事項、提供済みのコードサンプルを熟読するため。
4. `docs/03_implementation/03_implementation_common_patterns.md`
   最新のコーディング規約（環境変数カスケードパターンの `export` -> `${VAR:-}`、`shellcheck` 基準、エラーハンドリング `set -euo pipefail` など）を再確認するため。

## Step 2: 移行元・分析資料の確認

- タスクが既存のWindows `.bat` の変換を伴う場合、`docs/01_analysis/` 配下の該当する解析ドキュメント、または既存のバッチファイル本体を `view_file` で読み込んでください。
- 元のコードの「目的（何をするバッチか）」を理解した上で、Ubuntuネイティブなやり方（`chcp` 廃止、`SCRIPT_DIR` を使った絶対パス管理、等）で再構築する設計を立ててください。

## Step 3: コード実装

1. 対象の `.sh` ファイルを作成、または修正します。
2. ファイル先頭には必ず `#!/bin/bash` と `set -euo pipefail`、およびエラー補足の `trap 'echo "Error on line $LINENO"; exit 1' ERR` を記述します。
3. インストーラー起点、もしくは下流のセットアップのスクリプトの場合は**「環境変数カスケードパターン」**（親は`export`、子はフォールバック評価）に従っていることを必ず確認してください。

## Step 4: 検証とテスト実行

実装が終わったら、`run_command` を使ってターミナルで動作確認を行います。
1. `shellcheck -e SC1091 /path/to/script.sh` を実行します。
2. 警告やエラーが出た場合はすべて修正してください（※カスケード用の変数を未使用として勝手に削除しないこと）。
3. 影響のない範囲でテスト実行（ドライランやサブシェルでの呼び出し）を行い、ロジックが正常に機能するか検証します。

## Step 5: チェックリスト更新とコミット

1. `docs/04_reference/04_reference_checklist.md` を編集し、該当タスクの `[ ]` を `[x]` に変更します。
2. `git add` と `git commit -m "Phase X Task Y.Z: [日本語のコミットメッセージ]"` を `run_command` で実行します。
3. ユーザーに完了を報告し、次のタスクへ進めるかどうかの指示を仰ぎます。
